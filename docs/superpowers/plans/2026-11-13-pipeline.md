# Pipeline di rilascio — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Frequenza Dev e Frequenza installabili insieme, con le pipeline GitHub Actions di PackLog adattate: controlli sulle PR, versione dalle etichette, APK dev su Telegram, rilascio firmato verso il test chiuso, promozione manuale, scheda dello Store.

**Architecture:** Flavor Android `dev`/`prod` su un solo `main.dart`. Logica delle versioni in un modulo Node condiviso dai due workflow che la usano, così è testabile. Icona disegnata da uno script Python senza dipendenze, che produce sia i vettori adattivi sia i PNG. Un test Python legge i workflow e blocca gli anti-obiettivi del design.

**Tech Stack:** Gradle Kotlin DSL, GitHub Actions, `actions/github-script`, `r0adkll/upload-google-play`, fastlane `supply` 2.225.0, Python 3 (stdlib + PyYAML), Node 24 (`node --test`).

**Spec:** `docs/superpowers/specs/2026-11-12-pipeline-design.md`
